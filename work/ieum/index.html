서비스 소개

고령층이 모바일에서 음성으로 금융 업무를 시작하고, 온라인 처리가 어렵거나 대면 도움이 필요할 때 영업점 방문으로 이어갈 수 있도록 만든 서비스입니다.

서비스 전체에는 음성 해석과 금융 업무 기능이 함께 있습니다. 직접 담당한 부분은 채널 판정·업무 상태·방문 예약·생활 일정 연계와 음성 재시작 장애 수정입니다.

사용 흐름

  1. 1사용자가 음성으로 업무 요청
  2. 2업무 정보 확인 및 처리 채널 판단
  3. 3사용자 동의 후 영업점·시간 선택
  4. 4예약 확정 및 업무 상태 반영

기술 구성과 역할

Flutter · Dart
모바일 화면과 음성 입력을 연결합니다. 담당한 음성 수정에서는 종료 콜백, 재시작, 취소 시점의 상태를 제어했습니다.
Spring Boot
채널 판정, 업무 상태 및 방문 예약을 처리하는 백엔드입니다. 업무 모듈은 Port/Adapter 계약으로 연결했습니다.
PostgreSQL
예약과 시간 슬롯의 상태를 관리합니다. 확정 단계에서 잠금·재검증·조건부 차감을 적용하고 관련 변경을 트랜잭션으로 묶었습니다.

담당 기능 및 구현 과정

상황

예약 조회 후 확정하기 전 다른 요청이 좌석을 사용할 수 있고, 음성 인식 종료 콜백도 재시작 요청과 겹칠 수 있었습니다.

과제

예약의 중복 확정·취소를 제어하고, 오래된 음성 작업이 현재 상태를 변경하지 않도록 처리해야 했습니다.

실행

영업점 방문 예약

여러 시간 슬롯을 사용하는 상담을 예약할 수 있도록 연속 슬롯의 가용성 판정을 공통화했습니다. 조회 이후 다른 예약이 들어올 수 있으므로, 확정 요청에서는 해당 슬롯을 잠근 뒤 가용성을 다시 확인하고 조건부로 좌석을 차감했습니다.

예약 확정·취소 및 업무 상태

예약 생성, 슬롯 점유, 업무 완료를 한 트랜잭션으로 처리했습니다. 같은 업무를 다시 확정하면 기존 예약을 반환하도록 했고, 취소 요청이 반복돼도 좌석 복원은 한 번만 반영되도록 구성했습니다.

채널 판정 및 생활 일정 연계

업무 조건, 이력, 재시도, 도움 요청을 기준으로 대면 도움이 필요한 상황을 판정했습니다. 도움을 제안하는 단계와 실제 업무 상태 변경을 나눠, 사용자의 동의 전에는 상태가 바뀌지 않도록 했습니다. 생활 일정과 업무 모듈의 연결에는 Port/Adapter 계약을 사용했습니다.

음성 인식 재시작

첫 발화 이후 마이크가 다시 열리지 않는 장애에서 종료 콜백과 재시작 요청의 실행 순서를 추적했습니다. 재시작 경로를 하나로 모으고 세대 토큰을 적용해 이전 비동기 작업의 늦은 완료가 현재 상태를 바꾸지 못하도록 했습니다. 무응답 폴링은 전체 제한 시간의 남은 시간을 기준으로 종료하도록 했습니다.

결과

예약 재확정·멱등 취소와 음성 재시작의 예외 경로를 구현하고 회귀 시나리오로 확인했습니다. 팀은 2026 KB IT’s Your Life 해커톤에서 장려상을 받았습니다.

설계 판단

1. 예약 확정 시점 재검증

조회와 확정 사이 가용 좌석이 달라질 수 있어, 확정 단계에서 잠금과 재검증을 수행했습니다.

2. 사용자 동의와 상태 변경

대면 도움을 제안하는 조건과 업무 상태를 바꾸는 조건을 구분했습니다. 사용자 확인 전에는 상태를 변경하지 않도록 고려했습니다.

3. 비동기 작업 구분

취소된 작업의 콜백이 뒤늦게 도착하는 경우를 고려해 세대 토큰을 사용했습니다. 종료 시간은 개별 폴링이 아니라 전체 제한 시간으로 관리했습니다.
