문제

→

이체 정합성 설계

부모와 자녀가 계좌·저축 목표·금융 기록을 함께 관리하는 서비스입니다. 이체, 알림, 가족 초대, 월간 리포트의 설계와 구현을 담당했습니다.

문제

화면의 중복 클릭 방지만으로는 네트워크 재전송이나 동시 출금을 통제하기 어렵습니다. 일부 데이터만 반영되면 잔액과 거래내역이 어긋날 수 있습니다.

설계와 구현

UUID 멱등키와 UNIQUE 제약으로 중복을 방어하고, 계좌 ID 순서로 비관적 락을 획득했습니다. 조건부 출금과 단일 트랜잭션으로 잔액·거래내역·상태를 함께 처리했습니다.

01중복 요청 검사UNIQUE KEY
→
02순서대로 잠금FOR UPDATE
→
03함께 반영·롤백TRANSACTION

구현 결과 중복 실행과 부분 반영을 방어하는 이체 구조를 마련했습니다. 이체는 프로젝트 내부의 모의 거래 흐름으로 구현했습니다.

조회 패턴을 기준으로 알림 설계

k6로 15·10·5초 폴링 주기를 비교하고, 테스트 회원 20명에게 5초마다 신규 알림을 생성하는 총 2,380건 조건에서 생성과 조회를 함께 점검했습니다. after_id 기반 Keyset Pagination과 복합 인덱스를 적용하고, 백그라운드 중단·복귀 조회·지터·백오프를 설계했습니다.

데이터 용도에 맞춘 보호 방식

다시 표시해야 하는 계좌번호는 AES-256-GCM으로 암호화하고 조회용 해시를 분리했습니다. 초대 토큰은 원문 대신 SHA-256 해시를 저장하고, Refresh Token에도 해시 저장과 회전을 적용했습니다.

검증과 설계의 한계

계산·암복호화·상태 전이 단위 테스트, 권한·거래·중복 요청 서비스 테스트, Mapper SQL 및 Controller HTTP 계약 테스트로 계층을 나누어 검증했습니다. 이체 트랜잭션에 리포트 갱신이 포함된 구조는 리포트 실패가 이체까지 롤백시킨다는 결합도 과제를 남겼습니다.
